# Nutrition and care

Nutritionists manage the shared seven-day menu and overrides for their assigned players. Parents see the override when one exists, otherwise the current shared menu. An AI response is only an editable draft: generating it never publishes it. Reset removes an individual override.

Coaches also have a separate menu workspace for their currently assigned team players. “Propozo menu me AI” queues a durable proposal, which appears automatically when ready. The coach approves the stored proposal after confirming dietary review; the server rechecks team membership, role and menu revision. Repeated pending requests and repeated approvals do not create duplicate work or notifications. New nutrition referrals from coaches also route the draft to the requesting coach. Existing nutritionist drafts remain available to their assigned specialist.

The parent title is “Menuja ushqimore e klubit”. Coach approvals are attributed to the coach; only actual nutritionist publications are labelled as recommended by the club nutritionist. Individual menus have a visible badge and publication date. Changed menus queue push notifications inside the same database transaction for valid opted-in subscriptions. Shared-menu changes target only players who still use the shared menu. Superseded notifications are suppressed. Saving unchanged content does not send another notification; without push subscriptions the published menu remains visible in the portal.

Set `Gemini__ApiKey` in Railway Variables. Menu generation uses optional `Gemini__MenuModel`, defaulting to `gemini-3.5-flash-lite`; the older general `Gemini__Model` setting no longer controls menu requests. Local development reads ignored `appsettings.Local.json`; that file is excluded from publishing. Never commit keys. Gemini uses the official `generateContent` endpoint and `x-goog-api-key` header: https://ai.google.dev/api/generate-content .

Personal generation requires a birth date, weight and height. It sends age, dated latest weight and height, numeric latest performance/testing records, recent recorded session loads and the nutritionist's explicit dietary instructions. It does not send name, contact, date of birth, clinical notes or free-text coach notes. Missing performance data is not invented. Allergy review is required. The nutritionist must review the draft before publishing, particularly for minors or medical dietary needs. Model output is treated as plain text and validated as seven days of bounded fields.

The built-in shared menu is a general food template, not a calorie prescription. Background guidance: https://www.nhs.uk/live-well/eat-well/food-guidelines-and-food-labels/the-eatwell-guide/ . Portions, allergies and individual needs are for the nutritionist to review.

Coaches create referrals for their own active team's players. Assigned professionals see referrals of their specialty; cases remain pending until handled. Closing a referral does not change medical clearance. Medical clearance is based on the latest doctor entry on or before the attendance date. Unavailable blocks present attendance on the server and in the form; it persists after reassignment and until a new doctor assessment changes it. A review date does not automatically release a player.

New nutrition referrals queue a durable automatic menu draft. The worker scans every 3 seconds, uses the requesting coach for coach proposals or an active assigned nutritionist for specialist proposals, and sends the observation plus existing dietary recommendations and a compact summary of dated player metrics to Gemini. Observations are not treated as diagnoses. Missing specialist assignments remain pending; generation failures stop after one attempt; another request requires an explicit user action. A processing lease prevents concurrent instances from normally claiming the same job and recovers work after restart. A crash after the provider responds but before storage may require a repeated provider request. Closed cases are not processed. Older referrals are not automatically backfilled.

Automatic drafts appear in the requesting coach's menu workspace or the assigned nutritionist's workspace, depending on who requested them. They never alter the published parent menu until saved after allergy review. Stale drafts cannot overwrite a newer individual menu. Parents have four compact sections: progress charts, published menu, explicitly shared doctor instructions, and a psychologist placeholder. Progress exposes only selected numerical measurements and football ratings for the selected child; it excludes clinical notes, psychological assessments and internal coach comments.

Lightweight generation uses minimal thinking, a 2,200-token output cap, up to eight words per meal, and a 35-second request timeout. Full previous menus are omitted; existing dietary recommendations and explicit restrictions are retained without truncation. Provider-reported input/output/thinking/total usage is logged without prompts, player data or secrets. Model documentation: https://ai.google.dev/gemini-api/docs/gemini-3 .
