# Matches and playing time

Coaches and assistants open **Ndeshjet** from their panel. Only currently assigned active teams in the selected club are accessible. No match access is granted through a posted team/player ID alone.

Create a match first using the opponent, date, venue, optional kickoff and a competition choice: points (stored as Official for backward compatibility), cup or friendly. The creation endpoint saves a draft with no result or roster. Opening the created match reveals the score, lineup and playing-time editor. Duration and on-field capacity are editable for youth formats and different sports. Football defaults to 90 minutes/11 players, basketball to 40/5 and handball to 60/7. Other formats should have their duration and capacity entered by the coach. Match sport is saved historically.

The roster distinguishes starters, substitutes who played, unused substitutes and players outside the squad. Each playing interval uses cumulative minutes from match start, excluding breaks. Include extra/stoppage time in the entered duration. Resolution is one minute; this is a post-match/statistical editor, not a live official clock. The quick substitution control closes the outgoing player's interval and opens the incoming player's interval to match end. Re-entry is supported; the coach can adjust any interval before saving.

Only completed matches feed reports. They require a non-future date, both scores and actual playing intervals. Reports split points/cup/friendly minutes, starts, substitute appearances and unused bench selections. Drafts and cancelled matches are excluded. A player history link is available from the development profile. These records do not count as training attendance or create financial charges or parent notifications.

Server validation rejects overlapping intervals, negative/out-of-range minutes, excess players on the field, forged roster members and medical unavailability on match day. It permits playing short. Competition-specific substitution quotas and eligibility rules are not inferred. Existing historical roster entries remain editable after a player transfer/deactivation; new entries must be active members of the team. Medical restrictions still apply to historical edits at the match date.

Every save records an audit snapshot, actor and time. A revision prevents stale overwrites and a unique request ID prevents duplicate creation. All three new tables use club filters, write guards and composite foreign keys. Operational reset includes these tables in dependency order. Migration `MatchMinutes` adds tables only and is applied at normal app startup; existing club records are preserved.

Validation: `MatchChecks` exercises interval maths, rolling substitutions, unused reserves, official/friendly totals, draft/cancel exclusions, authorization, club isolation, idempotence, stale updates and medical restrictions. HTTP checks save a completed match using the actual MVC form. `--ui` uses isolated fixture data and browser viewports 320/390/768 px, tests interval controls and captures mobile screenshots. This is browser emulation, not a physical-device test.

Design references: [TeamStats match features](https://www.teamstats.net/all-teamstats-features) and [360Player match statistics](https://help.360player.com/en/articles/10201142-input-match-statistics). This implementation calculates totals from intervals so the coach does not need to enter a second independent minutes total.

## Football events and discipline

Football matches have an event grid for goals, penalties, own goals, opposition goals, assists and cards. Goal/assist participants must be in a recorded playing interval; the minute boundary is inclusive because this editor has minute resolution. Bench players may receive cards. The second caution automatically becomes a second-yellow dismissal. A dismissed player cannot have later playing minutes or be replaced on the field. Recorded goals may be partial but cannot exceed the entered score. Shootout goals are not supported as ordinary match goals. Completed reports aggregate goals (excluding own goals), assists, yellow cards and dismissals.

IFAB Law 12 establishes the second-caution dismissal and allows cautions/dismissals for substitutes: https://theifab.com/laws/latest/fouls-and-misconduct/ . It does not establish a universal accumulated-yellow suspension threshold. No FFK-specific threshold is asserted here. A coach explicitly confirms a rule for the team, competition type (points/cup/friendly) and date range. Distinct tournaments within one type are not yet separate disciplinary competitions. Unknown rules show a review warning; direct and second-yellow red cards can receive a recorded disciplinary decision with the suspension length, including zero for a rescinded penalty. Changes to events recompute subsequent warnings.

Warnings appear in the match list for the next scheduled match (or current date) and in the editor for prior matches. Only completed matches count. A suspension is served by a subsequent completed match in the same scope with the player outside the squad; bench selection does not serve it. The tool warns rather than prohibiting selection. Cross-team/season carryover, external matches, abandoned-match rulings and appeals require review; it is not an authoritative federation eligibility registry. Without a configured season, review warnings use July–June. These are in-app alerts, not push notifications.

Migration `FootballMatchEvents` adds JSON event data with an empty default and club-scoped discipline rules, preserving old matches. Rule edits are serialized with team writes, reject overlapping date ranges and stale revisions, and record the last actor/time. Event changes retain the existing match audit snapshots.

The team portal and team page link to a per-team matrix. Rows combine current active players (including those with no appearances) with historical participants in completed matches for the selected year/type. Columns show individual matches, minutes/role and football event counts; totals cover the entire selected period. Player names and column headers remain sticky inside the scrollable grid. Team access uses the same assigned-coach and club filters as the match report.

Football lineup editing now opens on a CSS/SVG pitch with named player cards, bench and remaining roster. The pitch represents the starting formation, not a live match timeline; substitute appearances remain in the bench section with updated minutes. Cards display this match’s minutes, goals, assists and cards. A modal offers role selection, enter/leave times, a paired substitution and goal/card shortcuts. Detailed intervals and assist editing remain available below. Formation and starter slots are stored with the match/roster in additive migration `MatchPitchFormation`; youth capacities use an automatic layout. Server capacity, interval, dismissal, medical and access checks remain authoritative. No image download or third-party pitch service is required.

The refined football workspace uses a locally drawn green striped pitch, initials avatars, formation-position badges and accessible metric icons. The selected card is highlighted. At desktop widths actions are docked below the reserve list; mobile/tablet uses the same controls in a native modal. Match metadata and the detailed interval table can be expanded. No generated bitmap or remote image is loaded by this UI.

Touch workflow: phones switch between Field and Reserves without horizontal pitch scrolling; tablets retain an adjacent reserve column. Pitch cards emphasize names/minutes and open full statistics and actions. The action sheet retains the last manually entered minute for the current page, offers one-minute steps and an explicit save button. It is not a running match clock and does not auto-save. An unsaved indicator distinguishes edits from persisted data.

Football now separates creation, starting lineup confirmation, match events and the final report. Drafts show lineup controls without event recording. Confirming requires starters with full initial intervals and changes the stored status to Live. While Live, starter identities, formation and on-field capacity are preserved; paired substitutions change playing intervals rather than replacing the starting roster. The player action sheet records goals/cards and asks for the other player and minute for a substitution. Finish requires confirmation, saves Completed and opens the authorized per-match Summary with scores, player statistics and a chronological event/entry/exit list. Live matches do not enter completed totals. Existing completed matches remain correctable. This status transition uses the existing string column and needs no additional migration.

Each match player can receive an optional coach rating from 1 to 5 and a note up to 1000 characters. The pitch action sheet uses touch-sized stars and an optional note; the detailed roster supports other sports. Ratings are per match, never defaulted to zero, included in audit snapshots, and displayed in the per-match report. Migration `MatchCoachAssessment` adds nullable columns, preserving older records.

Administrators and super administrators land on a club-scoped teams/matches dashboard in Home, with live, upcoming, completed and other games in flat grids, team/year filtering and a read-only match report. Coach edit endpoints remain coach-only. The selected club filter applies to all dashboard and report queries; owner club selection remains unchanged. Other staff home views are preserved.

The administrator landing page now shows only the current local calendar week (Monday inclusive through the following Monday exclusive), including weeks crossing month/year boundaries. Seven dated day anchors highlight today; matches appear in chronological order as responsive cards with result or kickoff, status and report link. Empty days stay compact. Team filtering stays club-scoped. This card layout is the explicit user-requested exception to the general grid preference.

Touch event entry uses player card -> goal/yellow/red/substitution -> minute -> register. Substitution choices are touch buttons containing only unused bench players with no intervals, dismissal or medical notice. The outgoing player must still have an open interval to match end. Quick football substitutions do not allow re-entry; detailed historical intervals remain available for corrections. The lower add-goal/add-card buttons are removed; existing events can be reviewed/corrected in a collapsed section. Each action asks for its own minute, and cancellation does not change data. Second cautions still become dismissals. Explicit match saving remains required and is indicated by the unsaved state.

Administrator football reports include a read-only golden pitch using the saved starting formation/slots, with unused slots shown empty and reserves alongside (below on phones). Player badges show goal counts excluding own goals, cautions/dismissals and interval entry/exit minutes. Dismissal exits are not labeled as substitutions. The pitch represents the starting lineup with accumulated match events, not a live positional feed; no missing opponent roster or shirt numbers are invented. Other sports retain their existing report. The chronological timeline remains unchanged.

Clicking an administrator pitch/bench player opens an accessible dialog with current-match details and all-time club totals from completed matches: minutes, appearances, goals, assists, starts and substitute appearances. Unused bench selections do not count as appearances. Admin-only endpoints validate membership in the requested match and retain global club filters. Progress opens existing charts and care information read-only, with a fixed return link to the match; coach editing permissions are unchanged. Requests are abortable and failures display a retry message rather than stale player data.

Administrator player-card and linked progress totals include the currently opened match alongside completed matches, using a single OR-filtered query so a completed current match cannot be counted twice. Cancelled current matches are excluded. Other live/draft matches remain excluded. Current-match minutes are the saved intervals, not a running match clock.
